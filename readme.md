# PortableLLM для Windows 10

PortableLLM - это набор PowerShell-скриптов для разворачивания переносимой среды локального запуска текстовых нейросетей на Windows 10 и Windows 11.

Главная идея проекта: все компоненты устанавливаются не глобально в операционную систему, а в одну выбранную папку, например `H:\LLM`. Это может быть папка на диске, внешний SSD, флешка или другой переносимый накопитель.

Не создается конфликта с уже установленным и раблотающим софтом.

- В качестве интерфейса используется OpenWebUI.
- В качестве "движка" llama.cpp
- Модели - почти любые в формате gguf, с которыми справится видеокарта

Скрипты установки не запрашивают права администратора. Если PowerShell или Windows запрашивает повышение прав, это не является штатным требованием проекта.

Параметры запуска моделей уже подбирались и проверялись на тестовой машине с видеакартой NVIDIA 4060ti, но это не гарантия оптимальной работы на любом железе. Для дальнейшей оптимизации можно менять параметры в `config\portablellm.ini`: размер контекста, batch/ubatch, VRAM-запас, MoE-настройки, mmap и другие параметры `llama.cpp`.

## Быстрый старт

1. Скачайте CUDA 12 архив `llama.cpp` и соответствующий архив `cudart` из релизов [github.com/ggml-org/llama.cpp](https://github.com/ggml-org/llama.cpp). Например:
   1. llama-b8931-bin-win-cuda-12.4-x64.zip
   2. cudart-llama-bin-win-cuda-12.4-x64.zip
2. Положите оба архива рядом с `Install-PortableLLM.cmd`.
3. Запустите `Install-PortableLLM.cmd`.
4. Далее по запросу укажите папку установки, например `H:\LLM`, или только букву диска, например `H`.
5. После установки скопируйте одну или несколько `.gguf` моделей в папку `models`, например: `H:\LLM\models`.
6. Запустите `Start-PortableLLM.cmd` из целевой папки, например: `H:\LLM\Start-PortableLLM.cmd`. Произойдет следующее:
   1. Автоматически стартуют необходимые компоненты.
   2. Если в папке `models` более одной модели, то будет предложено выбрать определенную модель для загрузки.
   3. Откроется стартовое окно в браузере, например `http://127.0.0.1:3000`. Если данный порт занят, будет использован следующий свободный. Порт будет записан в `logs\last-url.txt`.
   4. При первом запуске будет предложено создать пользователя-администратора Open WebUI.
7. Для остановки используйте `H:\LLM\Stop-PortableLLM.cmd`.

Если порт `3000` занят, стартовый скрипт автоматически выберет другой свободный порт и запишет его в `logs\last-url.txt`.

## Какую задачу решает этот проект

Проект позволяет подготовить на Windows 10 / 11 локальную среду для запуска `.gguf` моделей через `llama.cpp` и работы с ними через веб-интерфейс Open WebUI.

После установки пользователь получает portable-папку, внутри которой находятся:

- embedded Python;
- Open WebUI и его Python-зависимости;
- `llama.cpp` с `llama-server`;
- CUDA 12 runtime DLL для CUDA-сборки `llama.cpp`;
- папка для моделей;
- конфиг;
- быстрый перезапуск только `llama-server` с временными переопределениями конфигурации;
- логи;
- скрипты запуска, быстрого перезапуска модели и полной остановки.

Установка не должна требовать глобального Python, изменения системного `PATH`, установки в `Program Files` или ручного раскладывания файлов по системным папкам.

## Почему не взять готовое решение

Готовые решения часто удобны, но плохо совпадают с задачей именно переносимой Windows-среды:

- Многие установщики ставят компоненты глобально в систему.
- Часто используются системные каталоги профиля пользователя, `%APPDATA%`, `%LOCALAPPDATA%`, глобальный Python или Docker.
- Не всегда прозрачно, где лежат модели, кэши, логи и настройки.
- Не всегда удобно контролировать параметры `llama.cpp`, которые важны для производительности, VRAM и больших GGUF-моделей.
- Не всегда удобно перенести готовую установку на внешний накопитель и использовать ее как самодостаточную папку.

Этот проект сделан как простой и проверяемый portable-установщик: все важное лежит внутри одной папки, а запуск устроен через обычные `.cmd` и `.ps1` файлы.

Вывод: готового решения, которое соответствовало бы базовым требованиям проекта - Windows 10, portable-папка, отсутствие глобальной установки, явный контроль `llama.cpp` и возможность работы с внешнего накопителя, - не нашлось.

## Компоненты проекта

В проекте используются:

- `llama.cpp` - сервер локального запуска GGUF-моделей.
- CUDA 12 сборка `llama.cpp` для NVIDIA GPU.
- Отдельный архив `cudart` из того же релиза `llama.cpp`, содержащий CUDA runtime DLL.
- Open WebUI - локальный веб-интерфейс для общения с моделью.
- Embedded Python 3.12.3 для запуска Open WebUI без глобального Python.
- PowerShell 5.1, штатный для Windows 10.
- Простые `.cmd` обертки для запуска и остановки из корня portable-папки.

CUDA Toolkit проект не устанавливает. Нужен установленный NVIDIA-драйвер, а runtime DLL берутся из архива `cudart` соответствующего релиза `llama.cpp`.

## Требования

- Windows 10.
- PowerShell 5.1.
- NVIDIA GPU.
- NVIDIA-драйвер, совместимый с CUDA 12.
- Не менее 5 GB свободного места в целевой папке без учета моделей.
- Интернет на этапе установки Python-пакетов Open WebUI.
- GGUF-модель, которую пользователь самостоятельно кладет в папку `models`.

Практически для больших моделей важнее всего объем VRAM. Например, модель около 12-13 GB может запускаться на видеокарте с 16 GB VRAM, но запас будет небольшим.

## Что нужно скачать заранее

Рядом с `Install-PortableLLM.ps1` должны лежать архивы:

- `llama*.zip` - Windows x64 CUDA 12 сборка `llama.cpp`;
- `cudart*.zip` - CUDA runtime архив из того же релиза `llama.cpp`.

Важно: `cudart` должен быть именно для CUDA 12 и скачан вместе с тем же релизом `llama.cpp`. Иначе `ggml-cuda.dll` может не загрузиться, а запуск на GPU не состоится.

Пример файлов:

```text
llama-b8931-bin-win-cuda-12.4-x64.zip
cudart-llama-bin-win-cuda-12.4-x64.zip
```

## Установка

1. Скачайте или подготовьте CUDA 12 архив `llama.cpp` из релизов проекта [ggml-org/llama.cpp](https://github.com/ggml-org/llama.cpp).
2. Скачайте соответствующий архив `cudart` из того же релиза.
3. Положите оба архива рядом с `Install-PortableLLM.ps1`.
4. Запустите `Install-PortableLLM.cmd` или `Install-PortableLLM.ps1`.
5. Введите целевую папку установки, например `H:\LLM`, или только букву диска, например `H`.
6. Проверьте план установки на экране.
7. Подтвердите установку вводом `Y`.

Если введена только буква диска, например `H`, установщик выберет путь:

```text
H:\LLM
```

Поддерживаются файлы `.gguf`.

## Запуск

Обычный запуск:

```text
LLM\Start-PortableLLM.cmd
```

Скрипт:

- проверит CUDA backend;
- предложит выбрать модель, если в `models` лежит несколько `.gguf`;
- проверит приблизительное соответствие модели свободной VRAM;
- запустит `llama-server`;
- запустит Open WebUI;
- покажет локальный URL, например `http://127.0.0.1:3000`.

После завершения ответа Open WebUI показывает рядом с кнопками сообщения общую скорость генерации, например `15.8 tok/s`. Значение включает весь выход модели: рассуждение и финальный ответ.

Если порт `3000` занят, будет автоматически выбран следующий свободный порт, например `3001`.

## Остановка

Остановка:

```text
LLM\Stop-PortableLLM.cmd
```

Скрипт останавливает процессы `llama-server` и Open WebUI, запущенные из этой portable-папки.

## Настройка

Основной конфиг:

```text
LLM\config\portablellm.ini
```

Важные параметры:

```ini
GpuLayers=all
CtxSize=16000
CacheTypeK=f16
CacheTypeV=f16
BatchSize=2048
UBatchSize=512
Fit=on
FitTargetMiB=2048
ParallelSlots=1
PromptCacheMiB=0
NoContextShift=true
NoMmap=false
CpuMoe=false
NCpuMoe=
Metrics=true
ReasoningFormat=deepseek
VramReserveGb=2.0
```

Кратко по смыслу:

- `GpuLayers=all` - пытаться выгрузить модель на GPU полностью.
- `CtxSize=16000` - стартовый размер контекста.
- `CacheTypeK=f16` и `CacheTypeV=f16` - типы K/V-кэша. Для эксперимента с большим контекстом можно использовать одинаковые `q8_0/q8_0`.
- `Fit=on` - разрешить `llama.cpp` подбирать некоторые параметры под доступную память.
- `FitTargetMiB=2048` - желаемый запас VRAM.
- `ParallelSlots=1` - один активный слот генерации, чтобы не дробить память.
- `PromptCacheMiB=0` - prompt cache отключен для предсказуемости.
- `NoContextShift=true` - не сдвигать контекст бесконечно при переполнении.
- `NoMmap=false` - использовать memory mapping модели.
- `CpuMoe=false` и `NCpuMoe=` - параметры для MoE-моделей, по умолчанию выключены.
- `Metrics=true` - включить `/metrics` у `llama-server`.
- `ReasoningFormat=deepseek` - формат reasoning для Qwen-подобных thinking-моделей.
- `VramReserveGb=2.0` - запас VRAM для предварительного предупреждения.

После изменения базового `portablellm.ini` нужно остановить и заново запустить PortableLLM. Для временного эксперимента без перезапуска Open WebUI используйте `restartllm.ini` и быстрый Restart, описанный ниже.

## Быстрый перезапуск модели

`Restart-PortableLLM.cmd` перезапускает только `llama-server`. Open WebUI продолжает работать и после загрузки модели снова обращается к серверу по тому же адресу.

Экспериментальные переопределения задаются в:

```text
LLM\config\restartllm.ini
```

Файл может быть пустым. Перед каждым перезапуском скрипт заново объединяет безопасный базовый `portablellm.ini` и `restartllm.ini` в:

```text
LLM\temp\portablellm_tmp.ini
```

Если ключ указан в `restartllm.ini`, он заменяет базовое значение. Отсутствующие ключи берутся из `portablellm.ini`; предыдущий временный файл не используется как основа.

Пример:

```ini
CtxSize=30000
CacheTypeK=q8_0
CacheTypeV=q8_0
BatchSize=512
UBatchSize=256
```

Технически overlay может содержать любые параметры без whitelist и дополнительных ограничений. Следует учитывать, что быстрый Restart перезапускает только `llama-server`: уже работающий Open WebUI не перечитывает собственные параметры, а изменение `LlamaPort` может разорвать его текущее подключение.

Последовательность Restart:

1. Собрать effective-конфигурацию и показать различия.
2. Остановить только `llama-server`.
3. Подождать освобождения памяти; пауза по умолчанию равна 5 секундам и может быть изменена через `RestartDelaySeconds`.
4. Предложить обычный выбор модели — можно выбрать прежнюю или другую GGUF.
5. Выполнить оценку VRAM.
6. Запустить новый `llama-server`; Open WebUI не перезапускается.

Обычный `Start-PortableLLM.cmd` всегда читает только `portablellm.ini` и возвращает систему к базовым настройкам.

## Улучшенная оценка VRAM

Перед загрузкой Start и Restart пытаются запустить штатный `llama-fit-params.exe` с теми же параметрами модели. В выводе отдельно показываются:

```text
model + context + compute = всего; свободно; ожидаемый остаток
```

Статусы:

- `safe` - ожидаемый остаток не меньше `FitTargetMiB`;
- `low VRAM margin` - модель помещается, но желаемый запас не выдержан;
- `oversubscribed` - расчёт превышает доступную VRAM.

Оценка не блокирует запуск. Если `llama-fit-params.exe` отсутствует или не возвращает распознаваемый результат, используется прежняя грубая оценка размера GGUF плюс `VramReserveGb`.

## Проверка, что используется GPU

Признаки нормальной CUDA-работы:

- в диспетчере задач занята видеопамять;
- при генерации растет загрузка GPU;
- в `logs\llama.err.log` есть строки вроде `loaded CUDA backend`;
- в `logs\llama.err.log` есть строки `offloaded ... layers to GPU`;
- `logs\cuda-check.log` показывает NVIDIA/CUDA устройство.

Пример полезных строк:

```text
load_backend: loaded CUDA backend
load_tensors: offloaded 65/65 layers to GPU
sched_reserve: Flash Attention was auto, set to enabled
```

## Типовые проблемы

### Не найден архив llama.cpp

Проверьте, что рядом с установщиком лежит Windows x64 CUDA 12 архив `llama*.zip`.

### Не найден архив cudart

Проверьте, что рядом с установщиком лежит `cudart*.zip` из того же релиза `llama.cpp`.

### Open WebUI не открывается на 3000

Порт `3000` может быть занят. Посмотрите `logs\last-url.txt` или вывод стартового окна. Скрипт выбирает свободный порт автоматически.

### Не добавлено ни одной модели

Если в папке `models` нет ни одного `.gguf` файла, запуск остановится с понятной ошибкой. Скопируйте хотя бы одну GGUF-модель в:

```text
LLM\models
```

### Модель работает на CPU

Это считается ошибкой для данного проекта. Проверьте:

- наличие NVIDIA GPU;
- актуальность драйвера;
- наличие `ggml-cuda.dll`;
- наличие `cublas64_12.dll`, `cublasLt64_12.dll`, `cudart64_12.dll` рядом с `llama-server.exe`;
- файл `logs\cuda-check.log`.

### Модель не помещается в VRAM

Скрипт заранее делает грубую оценку по размеру GGUF и запасу `VramReserveGb`, но точный расход зависит от контекста, KV-cache, batch, типа модели и параметров `llama.cpp`.

Варианты действий:

- выбрать меньшую модель;
- выбрать более сильное квантование;
- уменьшить `CtxSize`;
- для MoE-моделей попробовать `CpuMoe=true` или `NCpuMoe=N`;
- уменьшить `GpuLayers`, если допустим частичный CPU offload.

### Генерация кажется медленной

Проверьте:

- действительно ли все слои ушли на GPU;
- не идет ли длинное reasoning-размышление;
- какой `CtxSize` используется;
- сколько свободной VRAM осталось;
- что показывает `/metrics` у `llama-server`.

Адрес метрик обычно:

```text
http://127.0.0.1:8080/metrics
```

## Portable-ограничения

Проект старается держать компоненты внутри целевой папки, но есть практические ограничения:

- Open WebUI и Python-пакеты могут иметь внутренние механизмы кэширования.
- Windows и драйвер NVIDIA остаются внешней системной зависимостью.
- При переносе на другой компьютер нужна совместимая NVIDIA GPU и драйвер.
- Внешний накопитель может менять букву диска, поэтому запуск лучше делать из корневых `.cmd` внутри portable-папки.

## Безопасность

Open WebUI запускается локально на `127.0.0.1`. Проект не предназначен для публикации интерфейса в интернет без отдельной настройки безопасности, паролей, firewall и reverse proxy.

При первом входе Open WebUI попросит создать администратора.

## Разработка

Репозиторий хранит только корневые `.ps1`, `.cmd` и `.md` файлы. Подпапки, модели, архивы, логи и установленная portable-среда не должны попадать в git.

Перед коммитом полезно проверить:

```powershell
git status --short
```

Для синтаксической проверки PowerShell можно использовать:

```powershell
$errors = $null
$tokens = $null
[System.Management.Automation.Language.Parser]::ParseFile((Resolve-Path '.\Install-PortableLLM.ps1'), [ref]$tokens, [ref]$errors) | Out-Null
$errors
```

## Текущее состояние

Проект находится в рабочей стадии: установка, запуск, остановка, выбор моделей, CUDA 12 runtime, Open WebUI, проверка VRAM и базовые параметры `llama.cpp` уже протестированы на локальной portable-установке.

Оптимизация производительности и подбор параметров для конкретных моделей остаются отдельной задачей, потому что результат зависит от модели, квантования, видеокарты, драйвера и размера контекста.
