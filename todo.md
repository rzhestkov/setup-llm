Ниже — переписанная версия промпта с явной фиксацией исходной цели проекта.
Главный акцент: это не просто набор скриптов, а portable-установщик для Windows 10, который разворачивает среду локального запуска текстовых LLM целиком в выбранную папку, в первую очередь на внешнем накопителе.

---

```text
Задача: написать набор PowerShell-скриптов (совместимость PowerShell 5.1) для Windows 10, которые разворачивают полностью переносимую (portable) среду для локального запуска текстовых нейросетей.

========================================
## ИСХОДНАЯ ЦЕЛЬ ПРОЕКТА

Нужно сделать portable-установщик программного обеспечения для Windows 10, которое позволяет локально запускать текстовые нейросети.

Ключевое требование:
установка не должна производиться глобально в операционной системе.

Это означает:
- ничего не устанавливать в Program Files
- не использовать глобально установленный Python
- не менять системный PATH
- не требовать admin-прав
- не делать систему зависимой от этой установки

Все файлы, зависимости, данные, логи, модели и runtime-компоненты должны размещаться только внутри целевой папки установки.

Скрипты не должны оставлять рабочие данные вне portable-папки:
- не использовать системные каталоги как основное место хранения данных
- не складывать рабочие файлы в %APPDATA%, %LOCALAPPDATA%, %USERPROFILE%, системный TEMP/TMP
- временные файлы, кэши, логи, конфиги и служебные данные должны жить внутри TargetPath

Приоритетный сценарий:
целевая папка находится на внешнем накопителе (USB-флешка, внешний SSD, внешний HDD), чтобы готовую среду можно было переносить между машинами.

После завершения установки пользователь должен иметь возможность:
1. подключить накопитель к ПК с Windows 10
2. запустить стартовый скрипт
3. локально работать с текстовой LLM через llama.cpp + Open WebUI
4. по возможности не зависеть от повторной установки компонентов в систему

========================================
## ЧТО ИМЕННО НУЖНО СОЗДАТЬ

Нужно сгенерировать 3 PowerShell-скрипта:

1. Install-PortableLLM.ps1
2. Start-PortableLLM.ps1
3. Stop-PortableLLM.ps1

========================================
## СОСТАВ PORTABLE-СРЕДЫ

В состав portable-среды должны входить:
1. Open WebUI
2. llama.cpp (llama-server)
3. Portable Python 3.12
4. скрипт запуска
5. скрипт остановки

========================================
## ОСНОВНОЙ ПРИНЦИП РАЗВЕРТЫВАНИЯ

Все компоненты должны быть развернуты внутри одной корневой папки, например:

<TargetPath>\
  OpenWebUI\
    data\
    packages\
  llama.cpp\
    bin\
  python\
  models\
  logs\
  config\
  scripts\
  temp\

Скрипты должны работать с путями аккуратно, через Join-Path, без хардкода системных директорий.

========================================
## ВХОДНОЙ ПАРАМЕТР УСТАНОВКИ

Предпочтительный вариант вызова:

.\Install-PortableLLM.ps1 -TargetPath "F:\PortableLLM"

Где:
- TargetPath — папка, в которую нужно развернуть всю portable-среду
- эта папка может находиться на внешнем накопителе

Если удобно, допустимо дополнительно поддержать сокращённый сценарий:

.\Install-PortableLLM.ps1 -DriveLetter "F"

но основным интерфейсом должен быть именно TargetPath, а не только буква диска.

========================================
## ФИКСАЦИЯ ВЕРСИЙ

Python:
- использовать portable Python ветки 3.12.x
- базовая протестированная версия: 3.12.3
- источник:
  https://www.python.org/ftp/python/3.12.3/python-3.12.3-embed-amd64.zip

Open WebUI:
- устанавливать через pip
- использовать совместимую стабильную версию
- базовая протестированная версия для данной сборки:
  open-webui==0.3.13

llama.cpp:
- использовать ZIP из GitHub Releases
- пользователь скачивает архив вручную
- скрипт не должен сам скачивать llama.cpp
- использовать вариант релиза: Windows x64 (CUDA 12)
- скрипты установки и запуска должны быть подготовлены именно под этот вариант сборки

========================================
## КРИТИЧЕСКИЕ ОГРАНИЧЕНИЯ

НЕ использовать:
- Docker
- npm/node
- winget/choco/scoop
- llama-cpp-python

НЕ скачивать автоматически:
- llama.cpp
- модели

НЕ выполнять глобальную установку в ОС:
- не прописывать системные переменные окружения
- не ставить Python в систему
- не создавать зависимости от глобальных пакетов
- не требовать установленного в системе CUDA Toolkit

ВСЕ данные:
- только внутри TargetPath

Служебные каталоги и переменные среды:
- при запуске перенаправлять TEMP и TMP внутрь TargetPath
- по возможности перенаправлять пользовательские кэши и служебные файлы приложений внутрь portable-папки

========================================
## ИСХОДНЫЕ ФАЙЛЫ

Рядом со скриптом установки должен находиться:
- llama*.zip (обязательно)

Ожидаемый тип архива:
- ZIP со сборкой llama.cpp для Windows x64 (CUDA 12)
- не CPU-вариант
- не Vulkan-вариант
- не другие backend-варианты

Если рядом несколько архивов llama*.zip:
- показать пользователю выбор

========================================
## ПОВТОРНАЯ УСТАНОВКА

Если TargetPath уже существует:
- не затирать содержимое молча
- показать пользователю, что установка уже существует
- предложить переустановку с подтверждением
- при подтверждении переустановки выполнить очистку и развернуть среду заново

Переустановка должна быть безопасной и понятной для пользователя.

========================================
## УСТАНОВКА PYTHON

1. Скачать:
   portable Python 3.12.x

   По умолчанию можно использовать:
   python-3.12.3-embed-amd64.zip

2. Распаковать в:
   <TargetPath>\python\

3. Включить site:
   раскомментировать import site

4. Установить pip:
   скачать get-pip.py
   выполнить локальным portable-python

5. Все действия производить без использования системного Python

========================================
## УСТАНОВКА Open WebUI

1. Использовать portable Python из:
   <TargetPath>\python\

2. Не использовать venv как основной механизм portable-развёртывания,
   так как venv на Windows может быть привязан к конкретному пути установки

3. Устанавливать Python-пакеты Open WebUI в локальную папку, например:
   <TargetPath>\OpenWebUI\packages\

4. Установить:
   pip install open-webui

   с размещением пакетов внутри portable-папки

5. Настроить DATA_DIR:
   <TargetPath>\OpenWebUI\data\

6. При запуске Open WebUI использовать только portable Python и локальные пакеты из TargetPath

7. Гарантировать, что Open WebUI использует данные только из portable-папки

========================================
## УСТАНОВКА llama.cpp

1. Найти llama*.zip рядом со скриптом установки

2. Если архивов несколько — дать выбрать

3. Проверить, что выбранный архив относится к сборке llama.cpp для Windows x64 (CUDA 12)

4. Если выбран не тот вариант сборки:
   завершить установку с понятной ошибкой

5. Распаковать во временную директорию:
   <TargetPath>\temp\llama\

6. Найти внутри распакованного содержимого:
   llama-server.exe

7. Скопировать папку с бинарниками в:
   <TargetPath>\llama.cpp\bin\

8. Если llama-server.exe не найден:
   завершить установку с понятной ошибкой

========================================
## ТРЕБОВАНИЯ К GPU И CUDA

Скрипт установки должен:

1. Проверить наличие NVIDIA GPU через WMI:
   Win32_VideoController

2. Проверить наличие:
   nvcuda.dll

3. Целевой сценарий проекта:
   Windows 10 x64 + NVIDIA GPU + llama.cpp Windows x64 (CUDA 12)

4. Скрипт не должен устанавливать CUDA Toolkit

5. Скрипт должен использовать готовую CUDA 12-сборку, уже входящую в выбранный ZIP-релиз llama.cpp

6. Требовать совместимость с CUDA 12.x на уровне драйвера NVIDIA

7. Не требовать глобальной установки CUDA Toolkit в систему,
   если используется готовый релизный ZIP llama.cpp с CUDA runtime

8. Если совместимая NVIDIA GPU и CUDA 12.x недоступны:
   вывести понятное предупреждение, что целевой GPU-сценарий не выполнен

Важно:
скрипт не должен пытаться сам переустанавливать драйверы или CUDA Toolkit.

CPU-only режим не является основным целевым сценарием проекта.

========================================
## МОДЕЛИ

Модели должны храниться в:

<TargetPath>\models\

Требования:
- использовать .gguf
- если моделей нет, стартовый скрипт должен вывести понятное сообщение и завершиться
- если моделей несколько, дать пользователю выбрать

========================================
## СКРИПТ ЗАПУСКА

Start-PortableLLM.ps1 должен:

1. Проверить наличие модели в <TargetPath>\models\
2. Прочитать настройки из текстового ini-файла:
   <TargetPath>\config\portablellm.ini
3. Если в конфиге нет портов или порт занят:
   автоматически найти свободные порты
4. Сохранить выбранные порты в ini-файл
5. Запустить llama-server
6. По умолчанию слушать только:
   127.0.0.1
7. Использовать порт llama из конфига
8. Передать параметр:
   -ngl 999
9. Использовать команду запуска, рассчитанную именно на CUDA 12-сборку llama.cpp
10. Проверить, что порт llama реально поднялся
11. Запустить Open WebUI
12. По умолчанию слушать только:
    127.0.0.1
13. Использовать порт Open WebUI из конфига
14. Проверить, что порт Open WebUI реально поднялся
15. Открыть браузер
16. Писать логи в:
    <TargetPath>\logs\llama.log
    <TargetPath>\logs\webui.log
17. Сохранять PID в:
    <TargetPath>\logs\llama.pid
    <TargetPath>\logs\webui.pid

При запуске нельзя требовать наличие глобальных зависимостей в системе.

При запуске также нужно:
- перенаправить TEMP и TMP внутрь <TargetPath>\temp\
- корректно работать с путями, содержащими пробелы и Unicode-символы

========================================
## СКРИПТ ОСТАНОВКИ

Stop-PortableLLM.ps1 должен:

1. Прочитать PID-файлы
2. Проверить, что PID действительно относится к процессу, запущенному из TargetPath
3. Попытаться корректно остановить процессы
4. Если не получилось — выполнить fallback kill
5. Удалить PID-файлы

Нельзя завершать чужие процессы только по совпадению PID.

========================================
## КОНФИГ И ФАЙЛЫ СОСТОЯНИЯ

Использовать текстовый ini-файл конфигурации:

<TargetPath>\config\portablellm.ini

В нём можно хранить:
- путь к выбранной модели
- порт llama-server
- порт Open WebUI
- путь к бинарникам llama.cpp
- режим запуска NVIDIA / CUDA
- другие настройки portable-среды

После установки сохранять текстовый файл с фактически установленными компонентами:

<TargetPath>\config\installed-versions.txt

В этом файле должны быть отражены:
- фактически использованная версия Python
- фактически установленная версия Open WebUI
- имя или версия выбранного архива llama.cpp
- вариант сборки llama.cpp: Windows x64 (CUDA 12)
- важные параметры сборки или запуска, если они определены во время установки

========================================
## ЛОГИ

Логи должны храниться в:

<TargetPath>\logs\
  startup.log
  llama.log
  webui.log

Логи должны помогать диагностировать ошибки portable-установки и запуска.

При необходимости можно вести дополнительный лог установки:

<TargetPath>\logs\install.log

## КРИТЕРИИ ГОТОВОСТИ

Результат считается успешным, если:

1. пользователь может выбрать папку установки на внешнем накопителе
2. все компоненты разворачиваются только внутрь этой папки
3. в системе не требуется глобальная установка Python или других компонентов проекта
4. запуск выполняется через Start-PortableLLM.ps1
5. остановка выполняется через Stop-PortableLLM.ps1
6. модели лежат в отдельной папке внутри portable-среды
7. после установки проект можно переносить вместе с папкой на другой совместимый ПК Windows 10
8. рабочие данные не уходят в системные пользовательские каталоги
9. сервисы по умолчанию слушают только localhost
10. состояние и порты сохраняются в текстовый ini-файл
11. фактически установленные версии сохраняются в текстовый файл
```
